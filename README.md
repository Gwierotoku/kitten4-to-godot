# Kitten4(.bcm4) → Godot 4 转换器

把**编程猫 Kitten4** 的工程文件 `.bcm4` 反向解析，生成**可直接在 Godot 4 里打开运行**的工程。

> **框架设计：Gwier** ｜ **程序实现：DeepSeek Harness** ｜ 项目负责人：**Gwier**

---

## 📌 这是个什么项目

`.bcm4` 是 Blockly 的序列化产物（与 Scratch 同源），里面装着两类东西：

| 类别 | 内容 |
| --- | --- |
| **逻辑** | 积木图：`blocks` + `connections` + `shadows` + `mutation` |
| **资产** | `theatre.styles`（造型）、`raw.audio`（声音），全部是内嵌 base64 |

所以转换器要同时解决两件事：**积木 → 代码**，以及**资产配置差异的桥接**。

整体架构不是"逐积木翻译"，而是：

```
.bcm4 ──解析──> 中间表示(IR) ──代码生成──> Godot 工程
                    ▲                          │
                    │                    运行时库(runtime/*.gd)
              资产抽取(assets)            ← 语义差异在这一层收敛
```

**核心设计：把"Kitten4 语义"与"Godot 实现"分离。**

- IR 层只描述 Kitten4 的语义（`op('key_pressed', [str('KEY_W')])`），不关心 Godot 怎么写
- 运行时库负责把 Kitten4 语义映射到 Godot（`K4Value` 值语义、`K4Sprite` 坐标/克隆、`K4Lib` 缺能力补偿）

收益是**语义修正只改一处**：例如发现 `add("","")` 应返回 `""`（字符串拼接）而非 `0`，只改 `K4Value.gd` 一个函数，113 个生成脚本全部受益。

## 📊 项目现状

### ✅ 目前能做什么

**简单作品的转换效果较好**——测试用例中涉及的功能**基本都已实现**。
用 `kitten示例项目/` 与 `测试用例/` 里的小型工程试，转换结果可以直接在 Godot 4 里跑起来。

**多屏幕（切屏）已能正确转换**。

### ❌ 已知问题与待优化项

**这个项目还远未完成。** 以下是明确已知的缺口，欢迎接力：

| # | 问题 | 影响 |
| --- | --- | --- |
| 1 | **广播触发存在问题** | 广播发送/接收的时序与作用域不可靠，多角色场景下尤其明显 |
| 2 | **画笔图层与角色图层仍存在问题** | 绘制内容与角色之间的层级顺序不正确，叠加显示会错乱 |
| 3 | **角色碰撞功能尚未实现** | 碰撞检测相关积木没有真正生效 |
| 4 | **物理功能没有实现** | 物理相关能力完全缺失 |
| 5 | **大型游戏性能不足（非常卡）** | 大型工程可以转换出来，但运行帧率很低，需要专门优化 |

> **性能问题已有实测记录，别从零开始。** 已知的一处明确瓶颈是**碰撞检测的朴素实现**：
> 512 个克隆体时每帧约 26 万次迭代，实测 **262 ms/帧**。
> 已用「同层角色列表每帧只收集一次 + 中心距平方预筛 + 包围盒同帧缓存」优化，
> `大陆漂移学说` 从 70~193 秒降到 **3.3 秒**。
> 详细数据与更多性能实验见 **`新版本/README.md`**（搜索"性能"）。
>
> **⚠️ 但大型工程整体仍然很卡，剩余瓶颈尚未定位——需实测（profile）确定。**
> 作者是一个人，精力有限，上面只是已知的大方向。究竟是代码生成、运行时库还是场景结构的问题，
> **必须实测才能定论**，欢迎接力者 profile 后反馈。

因此**重度依赖广播、碰撞、物理的作品目前无法正确转换**，**大型作品即便转换成功也跑不流畅**。

**本项目结构很乱，请 AI 先读文档再动手。**

具体地说：

2. **`新版本/` 才是唯一现役实现**，`_backup/`、`_out/`、`_cache/`、`_shots/` 都已通过 `.gitignore` 排除，请不要去仓库里找它们。
3. **强烈建议的阅读顺序**：
   - `技术路线汇报.md` — 整体设计思路与核心判断（**先读这个**）
   - `新版本/README.md` — 转换器的完整使用说明与架构细节（约 3200 行，最权威）
   - `笔记/新版本转换器_代码框架.md` — 代码框架
   - `笔记/草稿_core_js架构.md`、`笔记/草稿_emit_方法表架构.md` — 内核与代码生成器设计

5. **验证方式**：改动生成器或运行时后，跑 `新版本\_dev\regress.ps1` 做回归（转换 → 导入素材 → 真跑 300 帧 → 全量解析检查）。

## 🚀 快速开始

### 环境要求

| 依赖 | 说明 |
| --- | --- |
| **Node.js** | 运行转换器（[nodejs.org](https://nodejs.org)） |
| **Godot 4** | 运行生成的工程（建议 4.7.x） |

脚本会自动探测工具路径，也可以用参数或环境变量指定：

- 参数：`-NodePath <node.exe>`、`-GodotPath <Godot_v4.x-stable_win64.exe>`
- 环境变量：`$env:K4_NODE`、`$env:K4_GODOT`

### 一条命令：转换 + 验证

```powershell
cd 新版本
.\转换并验证.cmd "..\kitten示例项目\游戏-空白作品.bcm4" "_out\空白作品"
```

等价的 PowerShell 写法：

```powershell
& powershell -NoProfile -ExecutionPolicy Bypass -File .\huanzhuang.ps1 `
    -Bcm4 '..\kitten示例项目\游戏-空白作品.bcm4' -Out '_out\空白作品'
```

### 只要转换，不要验证

```powershell
cd 新版本
node convert.js '..\kitten示例项目\新的作品.bcm4' '_out\新作品' --clean
```

> **提示**：资源导入必须跑够。大型工程里 265 个造型有 165 个是 SVG，光栅化很慢，一次导不完。
> 判据是 **`.import` 文件数 == 素材文件数**（`huanzhuang.ps1` 会自动重试 3 遍）。
> 没导完就会在运行时刷 `No loader found for resource: ... .svg`。

```
│   │   ├── blocks.js              #   积木定义

│   │   └── 模板/                  #   生成工程的项目模板

│       ├── check_all.gd           #   全量解析检查器
│       └── 验证最小案例.ps1
├── kitten示例项目/                 # 示例 .bcm4 工程（含 18 MB 大型工程）
├── 测试用例/                       # 16 个测试用 .bcm4，覆盖各问题域（见上方）
├── 笔记/                          # 设计草稿与代码框架笔记
├── 技术路线汇报.md                 # ★ 整体设计思路（建议先读）
├── bcm4格式说明.md                 # .bcm4 文件格式说明
└── 技术路线汇报.docx               # 汇报文档（Word 版）
```
