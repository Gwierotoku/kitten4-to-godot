### 踩过的高价值坑（下次别重犯）

1. **`屏幕根()` 不能缓存**：帽子 `_ready`（注册监听）早于屏幕根脚本 `_ready`，那一刻算出来的是上层节点；缓存 → 该帽子永远判成"别的屏幕"。
2. **广播分屏要"发送时实时问"**监听者的 `_屏幕根()`，不能在注册时快照。
3. **GDScript 没有取消协程的原语**：`一步()` 在 `_已取消` 时只是"让出一帧再返回"，**循环会接着跑下一轮** → 必须由生成器在循环末尾补 `if ctx._已取消: break`。
4. **克隆体会继承帽子**：凡是"响应某事件的帽子 + 该帽子会克隆自己"的组合，都要用 `k4_is_clone` 把克隆体排除掉（绿旗、运行组激活都如此），否则**自我复制**；克隆体还会重跑脚本开头的赋值，把原体正在累加的全局变量**清零**。
5. **`一步()` 的 warp 预算拦不住"克隆自己"**：预算在每轮**末尾**检查，克隆开销发生在检查之前；一帧能造出几百个节点（峰值上万）。
6. **改造型结构时 pivot 偏移最容易丢**：SpriteFrames 的帧不带位移，必须自己带 `_造型偏移()` 表并在每次切造型时套用。
7. **改 `_掩码相交` 这类函数签名时，函数体里的旧参数名要一起改**（GDScript 只在编译期报 `Identifier not declared`，容易漏；改完用 `--check-only --script` 逐文件验一遍最快）。
8. **验证脚本的断言要防"采样巧合"**：5 个造型轮播 + 间隔 10 帧 → 两次采样可能落在同一帧，看起来"没变"。采样序列或"两次手动调用"更可靠。
9. **测试用的检查脚本会把屏幕场景挂到奇怪的位置**：`屏幕根()` 认"已登记的屏幕节点"就是为了这种情况；老逻辑（只认 root 直接子节点）会误判。
10. **"生成器写 `_配置XXX()`、运行时读 `@export XXX`" 是一类会静默失效的断线**：按键（§13.10）与广播（§13.4）都栽在这里 —— 症状是"功能完全不对/全部乱触发"，而生成物看起来完全正常。加新帽子时**两边成对写，并在验证脚本里断言实际效果**。
11. **浏览器 keyCode ≠ Godot Key**（只有字母数字重合）：方向键/回车/Esc/Tab 必须查表，`runtime/全局/按键表.gd` 与 `core.js KEY_CODE_NAMES` 要同步改。
12. **"转换写到 A、验证跑 B"（工具类，静默失败，最坑）**：`convert.js` 用 `path.resolve` 解析输出路径 = 相对**当前工作目录**，而 `huanzhuang.ps1` 第 2~5 步的验证目录按**脚本所在目录**算。从别的目录调用时 → 新产物落到 `<调用目录>\_out\x`，验证跑的却是 `新版本\_out\x` 里**上一次的旧产物** → 输出"全绿"，但这次转换**压根没被验证**（实测：`空白作品b` 报了 124 脚本 / 41 场景，那是该目录里旧工程留下的产物）。修：`huanzhuang.ps1` 转换前 `Push-Location $here`，并在转换后断言报告里的"转换完成: `<路径>`" == `$proj`。★凡"转换 + 验证"二段式工具，都要断言两段指向同一目录，并核对产物的修改时间★
13. **形参类型标错是"静默失效"重灾区**（两轮各栽一次）：列表形参写成 `'s'` → `列表添加(角色.转文本(列表), …)`（§13.11）；**名称形参**写成 `'s'` → `设置造型(角色.转文本(随机整数))` = `"5"`，而 K4 的造型名是 `"骰子（5）"`，匹配不上 → **造型根本没换**（§13.12②）。"编号或名字"这类值一律用 **`'v'`**；加新积木时逐个核对形参类型。
14. **K4 方向约定在"换算成数学角"处极易写反**：K4/Scratch 是 **0=上、90=右、顺时针为正**；`自带积木.移动_步` 旧代码写成 `deg_to_rad(k4_direction - 90)`，且上方注释自造了"0=下"的约定 —— 两个错误**互相自洽**，于是水平/垂直移动看着正常，**斜向和上下全反**（§13.12③）。正确：数学角 = `90 - 方向`（与 `角色基类._apply_transform` 的 `rotation` 配套）。
15. **验证脚本不要"边跑边动被测对象"**：我在 `stamp_check.gd` 里既 `set("k4_x", 0)` 又手动 `启动()`，而绿旗帽子**在场景加载时本来就会自动跑一轮** → 两条执行序交错，截图看着像"作品不整齐、头两个位置不对"，白怀疑了一轮。**只等它自己跑完再采样**。

## 0. 一句话框架

```
.bcm4(JSON)
  → core.js: parseProject → projectToIR ⇒ IR（纯语义，不含 Godot 写法）
  → convert.js: SVG 光栅化（改素材路径）
  → emit.js: emitProject(ir) ⇒ {files, report}（Godot 工程全部文本文件）
  → convert.js: 写盘 + 素材搬运 + runtime 拷贝 + 4 项自检 + 统计
  → huanzhuang.ps1: import → 真跑 300 帧 → 全量 parse 检查 → 数错误
```

设计原则（README §职责边界）：转换器只保证**结构正确 + 能打开 + 0 error/0 warning**；
积木的**功能实现**留在生成工程的 `全局/角色类.gd`（永不覆盖），缺口表现为**桩**。
"转换永不失败"：语义做不到的积木降级成 `pass` / 默认返回值 + 报告里记一条。

## 3. core.js 结构

### 3.1 BlockModel（66-222）—— 把 JSON 变成可遍历的图

- 构造时建三张索引：`connections`（父→子）、`nextOf`（语句顺序）、`parentOf[child]={parentId, kind:'next'|'input', inputName}`。
- `input(blockId, inputName)` (127) 三级回退：① connections 反查 → ② `parent_id` 退化（**仅当本块没有任何 input 连接**，否则语句输入的孩子会污染表达式）→ ③ `shadows` XML。
  - ③ 内还有关键一坑：影子块的**当前值**在 `blocks[影子id]`，XML 里只是创建时的默认值。
- `statementEntry` (188)、`topLevelIds` (201)、`statementChain` (209)。

### 3.2 IR 节点形态（224-242）

```js
{ k:'lit', v, num?:true, str?:true }   // num/str 是"按字段名判类型"打上的标记
{ k:'ref',     name }                  // 变量引用
{ k:'listref', name }                  // 列表引用
{ k:'op',      op, args:[] }           // 取值/语句操作（op 名对应 methodtable 的键）
```

### 9.1 K4 数据格式 / 反编译

1. 变量表键是 `raw.theatre.variables`（旧版读 `raw.variable` → 变量名永远解析不出）；列表是其中 `type==="list"` 的条目，**没有独立 list 表**。
2. 影子块的**当前值在 `blocks[影子id].fields`**，`shadows` XML 只是创建时的默认值（`text_split` 实例：XML 还是 `1,2,3,4`，真值是 100+ 字）。
3. 造型选择器存**两份**，影子那份可能是过期的；影子元素带 `id` → 该 id 的真实块 `fields` 才是当前值。
4. `math_number` 影子**同时装数字和文本**（数字在 `NUM`、文本在 `TEXT`）→ 必须**按字段名**判类型，不能按内容猜（`"0000000…"` 会被 parseFloat 成 0）。
5. 取值块的文本在 `VALUE` 影子（`shadow_text`），且 `expr()` 里对 shadow_* 有一个**提前返回**先于 switch —— 只改 switch 那个 case 永远不生效。
6. K4 与 Scratch 的输入名不同：`text_contain` 是 `TEXT1/TEXT2`、`text_split` 是 `TEXT_TO_SPLIT/SPLIT_TEXT`、`text_select_changeable` 是 `original_value`、取模是 `NUMBER_TO_CHECK/DIVISOR`、鼠标坐标字段是 `position`（不是 `scope`）。
7. 字段名不一致：`get_time` 用 `fields.op = year|month|date`（不是 timer）；舞台尺寸用 `fields.info = width|height`；`self_change_coordinate` 用 `coordinary` + `increase`；按键帽子用 `key_event_type = down|up`。
8. `self_move_to` = 「移到 x:__ y:__」（不是 Scratch 的"移到目标"）；K4 的"移到目标/面向"选择器在 `target` / `sprite` 字段。
9. 「角色属性」实参顺序要**反过来**（`角色属性(属性, 目标)`，而 K4 字段是 `sprite=角色` + `attribute=属性`）。
10. `ask_and_choose` 选项个数是**动态**的（`CHOICE0..n`），写死前两个会静默丢选项。
11. 未映射块不能丢 inputs：走 `stubStmt()` 落地成"带全部输入的桩"，缺口从"丢失的代码"变成"待填的桩"。
12. `self_glide_coordinate`、`ask_and_choose` 这类是**语句块**，必须挂 `stmt()`；挂到 `value()` 永远走不到。

### 9.2 生成 / GDScript

13. 调用点现在**无条件 await**（同步方法也合法，代价一次协程开销）——换确定性。
14. `MISSING_AWAIT` / `REDUNDANT_AWAIT` 是按**声明（含基类）静态判定**的：`_积木主体()` 基类实现里刻意留一个 await；启动用 `call("_积木主体")` 点火。
15. GDScript 重复参数名是**解析错误**，会表现成 "Could not resolve super class inheritance from 角色自带积木" 的连锁报错 → convert.js 自检③。
16. 同一个方法名出现在多张表且参数个数不同 → `buildSignatures` 去重 + 桩改名；否则场景加载失败。
17. `.tscn` 里节点名不能含 `.:@/"%[]`（`标题(1)` → `标题_1_`）；目录名清洗必须与 `sanitize` 一致。
18. 一个 `.tscn` 只能一个根节点：除首条外 `[node]` 必须带 `parent=`（运行期 load 看不见，只有编辑器拒绝加载）。
19. 参数被**补齐**（给少了）无害；被**截断**（给多了）必须报错（`argLoss`）。
20. 桩体形态：语句方法 `pass`，取值方法必须返回该类型默认值，否则 "并非所有路径都有返回值"。
21. 形参一律 `_` 前缀（避开基类成员 → SHADOWED_VARIABLE_BASE_CLASS）；成员不能和函数同名；子脚本不能重复声明父类 const/成员。
22. 不要用 `:=` 接返回 Variant 的调用（`全局变量.取值`）→ warning。
23. `int(null)` 在 4.7 会报错（桩默认返回 null）→ 循环走 `range(角色.转整数(...))`。
24. autoload 注册名必须 ASCII（中文名报 Identifier not declared），脚本文件名可保持中文。
25. 自定义积木名撞 GDScript 关键字（K4 里真有个函数叫 `pass`）→ `GD_KEYWORDS` 改名。
26. `var ctx := 角色.新建上下文()` 推不出类型 → 生成时显式 `var ctx: 角色基类.WarpCtx`。

### 9.3 运行时语义 / 性能

27. **`一步()` 在被取消的分支上必须让出**：否则"删除克隆体 + 另一个协程仍在 while 循环"会把主循环占死 = 窗口未响应（射击生存实测）。
28. warp 预算只在 `depth==0` 重置（嵌套 warp 会无限续期，实测第一帧跑十几秒）；另有**全帧共享**预算 `K4_帧warp预算 = 8ms`（Godot 特有，去掉 FPS→1）。
29. 画笔层序三层必须错开：舞台层 -100 / 画笔 -50 / 角色 0；`_draw()` 里**不要**铺底色（会盖掉背景板）。
30. K4 的画笔颜色是 **HSL**（不是 HSV）；碰撞**不要**统一到像素级（像素确认贵 15 倍，已加 `K4_帧像素确认上限 = 300` + 按字节读 alpha）。
31. 克隆体出生那一帧不参与碰撞；`角色属性` 实参顺序、计时器三态等都是实测修出来的。
32. 素材导入要多遍；`.import` 数 == 素材数才算导完，否则运行时 `No loader found for resource`。
33. `--quit-after` 在 headless 下不可靠（计时/帧数诊断要小心）；探针用 `--fixed-fps 60`。
34. SVG：Godot 的 SVG 导入器不认 `<text>`（丢字）和 `<image>` data:URI（整张变黑），一律光栅化成 PNG。
35. `.ps1` 要带 UTF-8 BOM，否则 PowerShell 5.1 按 ANSI 读，中文路径乱码（`huanzhuang.ps1` 本身刻意保持纯 ASCII）。

## 11. ★修改陷阱：同名 `case` 后者不可达（改错地方 = 白改）★

`core.js` 里 `expr()`（570-1121）与 `stmt()`（1311-2094）都是大 switch，历史追加时出现了**同一个 case 标签出现两次**的情况。
JS 的 switch 先匹配先执行，**后面那个永远不会被走到**（两处都带 `return`，不存在 fallthrough）。
全量扫描结果（已核实行号）：

| case 名 | 行号 | 判断 |
|---|---|---|
| `self_set_position` | **1437（生效）** / 1928 | ⚠**有语义差异**：生效版只按 `coordinary` 生成单轴 `set_coord`；1928 版还带"没有 coordinary 时按双轴 `goto_xy(x,y)` 兜底"（注释标了 ★实测修正★）。若 K4 真存在双轴形态，y 会被静默丢掉 → **要修必须改 1437** |
| `get_current_costume` | **704（生效）** / 718 / 1000 | ⚠**有语义差异**：生效版一律 `op('self_costume')`（读"当前造型"）；718 版本意是"把影子里的 `style_id` 解析成造型名"（造型**选择器**语义）。`set_costume` 分支已单独绕过（1384-1398），其它把该影子当选择器用的块仍可能受影响 |
| `get_time` | 679（生效） / 1015 | 两处逻辑等价 → 无害 |
| `lists_length` | 660（生效） / 1065 | 生效版带 `listref_from(列表, 序号)`（K4 的 VAR/INDEX 双输入）→ 更完整，无害 |
| `variables_set` / `data_setvariableto` | 1511/1512（生效） / 2041/2042 | 生效版走 `varName()` 解析 uuid → 名字；后者不解析 → 生效版更好 |
| `variables_change` / `data_changevariableby` | 1519/1520（生效） / 2044/2045 | 同上（生效版还处理 increase/decrease） |
| `lists_add` / `lists_delete` / `lists_replace` | 1532/1538/1554（生效） / 2047/2050/2059 | 生效版用 `listArgName` + `valueAny` → 更完整 |
| `procedures_callnoreturn` / `procedures_2_callnoreturn` | 1829/1828（生效） / 2074 | 生效版走 `procRoute`（local/remote）→ 更完整 |

**结论**：只有 ①`self_set_position` 的双轴兜底、②`get_current_costume` 的选择器语义 两处是"不可达代码里躺着一条可能更对的逻辑"。

| # | Bug | 根因 | 修法 |
|---|---|---|---|
| 1 | **接收方压根没注册监听** | 生成器写 `func _配置消息()`，而 `帽子_广播.gd` 读的是 `@export var 消息`（tscn 里也没有）→ `消息 == ""` → `_ready` 直接 return | 帽子_广播 新增 `_注册监听()`，消息名优先读 `_配置消息()`，`@export 消息` 留作兼容 |

**实测结果**（`_dev/broadcast_check.gd`，`--fixed-fps 60`）：

说明：①「广播」不等待（各自跑）；②「广播并等待」真的等到了接收方协程跑完；③ 跨角色、跨屏幕（2 个屏幕各 3 角色）都正常。

**实测结果 2 —— 多接收方 + 时长不同（`广播测试 (1).bcm4`，`_dev/broadcast_wait_check.gd`）**：
同一个消息「测试等待」有**两个**接收方，n3 抖 **1 秒**、n4 抖 **3 秒**：

| 时刻 | 事件 | 含义 |
|---|---|---|
| 1.050 s | 执行 = 1 | n3（快的那位）跑完 |

即：等待时长由**最慢的接收方**决定（3 秒），不是"等到第一个完成就走"（那样 n2 会在 1~2 秒就设 2）。

所以接收方里若套了不让出的无限循环，发送方就会一直卡在那里，与 K4 行为一致。

### 13.5 ★第二轮改动：custom（造型嵌套）修复 + 广播分屏隔离★

**A. 「切换到造型」的嵌套输入被吃掉（`custom测试 (1).bcm4`）**

症状：4 个「切换到造型」块生成出来**一模一样**（全是 `设置造型("新角色")`），
其中三个本该是嵌套表达式（`自己 的 造型编号`、`<角色> 的 造型名称`、`变量 + 0`）。

根因（`core.js` 的 `case 'set_costume'`）：`index` 输入其实有**两种形态**，
旧代码只处理了第一种，而且顺序反了：

| 形态 | `connections` 里 `index` 连到 | 数据特征 | 应该生成 |
|---|---|---|---|
| ① 下拉框 | **造型选择器影子** `get_current_costume` | `is_shadow=true` 且 `fields.style_id` | 造型名（`"新角色"`） |
| ② 嵌套表达式 | **真实功能块**（`get_3` 角色属性 / `math_arithmetic` / 变量…） | `is_shadow` 非 true，type 不是造型选择器 | 那个表达式 |

②的情况下 K4 **仍然**在 `shadows.index` 的 XML 里留着一份 `style_id`（创建时的默认造型），
旧代码找不到"影子 id 指向的真实块"就退回去读它 → 三个嵌套块全被替换成默认造型名。

修法：先看 `model.input(blockId,'index')` 连的是不是**真实功能块**（非影子且不是造型选择器）
→ 是就用 `expr()` 生成表达式；否则才走"造型名解析"。

**顺带修正**：实参类型校正里的 String 转换从 `str()` 改成 **`角色.转文本()`** ——
K4 的 `转文本(3.0)` = `"3"`，而 Godot 的 `str(3.0)` = `"3.0"`；造型编号/列表序号这类
"数字当名字用"的地方差一个 `.0` 就匹配不上。实测生成：
```gdscript
角色.设置造型("新角色")                                    # ① 下拉框
角色.设置造型(角色.转文本(角色.角色属性("2", "自己")))      # ② 自己 的 造型编号
角色.设置造型(角色.转文本(角色.角色属性("4", "新角色(1)")))  # ③ 别的角色 的 造型名称
角色.设置造型(角色.转文本(角色.算术运算("add", K4Global._v_变量, 0.0)))  # ④ 变量 + 0
```

跨角色造型名称拿到非空文本；表达式路径不会让角色落到"无效造型"上。

**B. 广播的两个语义确认 + 分屏隔离**

1. **不重入**（用户确认）：`帽子基类.启动()` 里 `if _运行中: return` —— 正在跑时收到同一广播
   不会重开一轮。已符合，无需改动。
2. **每个屏幕的广播各自独立**（用户确认）→ 本轮实现：
   - 旧实现的致命点：广播走 **Godot 信号**（`add_user_signal` + `emit_signal`），
     而信号是全局的，`emit` 一次必然触发所有连接者 —— **没法按屏幕过滤**。

**C. 帽子屏幕限定（用户确认的语义）**

> 除「当开始被点击时」「当作为克隆体启动时」外，**全是仅限当前屏幕执行的帽子**。

- `帽子基类` 新增 `_屏幕无关()`（默认 false）+ `_本屏幕当前()`；**`启动()` 里统一拦**：
  不是当前屏幕 → 直接 return。按键/点击/滑动/条件/计时器/响度/背景/广播/屏幕切换
  全都走 `启动()`，所以一处拦截全覆盖。
- `帽子_开始` / `帽子_克隆启动` 覆写 `_屏幕无关() → true`（点绿旗时各屏幕自己的绿旗脚本都要跑）。

**D. 屏幕身份的判定（踩了两个坑，很重要）**

`屏幕根()` / `_屏幕根()` = "本节点属于哪个屏幕"，广播分屏和屏幕限定都靠它。规则：

1. **① 向上找"已登记的屏幕节点"**（`K4Global.屏幕节点` 里的那个）；
2. ② 还没登记时退回结构判断（游戏屏幕容器的直接子节点 / root 的直接子节点）。

- 坑 1：只按"root 的直接子节点"找 → 屏幕场景挂在别的节点下时对不上，
  `屏幕是否当前()` 恒 false，**所有帽子被误拦**（广播回归就是这么挂的）。
- 坑 2：**不能缓存**结果。帽子的 `_ready`（注册监听）早于屏幕根脚本的 `_ready`，
  那一刻屏幕还没登记，算出来的是上层节点；缓存下来会让该帽子**永远**判成"别的屏幕"
  （实测：接收方收不到广播、执行值一直 0）。
- 因此监听者**不在注册时确定屏幕**：`K4Bus._可触发()` 在**每次广播时**实时问
  `目标._屏幕根()`（实例方法可能被重写，比注册时快照更可靠）。

### 13.7 ★第四轮改动：屏幕生命周期（即走即取消 / 切回重开）★

**起因**：`琪露诺的最强刨冰` 切换屏幕后帧时间爆炸（FPS 2、处理 1765ms、节点峰值 22481）。
调查结论：这作品有 **14 个「当切换到当前屏幕」帽子是常驻 `while true`**（其中 num/score_3/times/time_1_ 等每轮 `克隆自己`）。
旧版转换器根本不生成这些帽子（`on_running_group_activated` 上一轮才登记），所以"以前不炸、现在炸"；
而当时的屏幕限定**只在 `启动()` 时拦一次** —— **切走屏幕不会停掉已经在跑的协程** → 每切一次就多一套常驻脚本叠加 → 每帧创建/销毁大量角色节点（`克隆自己` = duplicate 整棵子树 + `初始化()`）。

**K4 语义（用户确认）**：非全局帽子「**即走即取消；切回所在屏幕重新开始**」。

| 环节 | 实现 |
|---|---|
| 取消钩子 | `帽子基类.取消运行()`：`_屏幕无关()` 的（绿旗/克隆启动）直接跳过；否则 `_ctx._已取消 = true` + `_结束运行()`（把 `_运行中` 落回 false 以便切回能重开，并 emit `_跑完` 唤醒正在「广播并等待」的发送方） |
| 激活钩子 | `帽子基类.屏幕激活()` 默认空；`帽子_屏幕切换` 覆写为 `启动()` → 切进来重新跑一轮 |
| 驱动 | 生成的 `K4Global.切换屏幕到()`：切走前 `_通知屏幕(旧, false)`，切换后 `_通知屏幕(目标, true)`；`_通知屏幕` 用 `find_children("*","",true,false)`（`owned=false` 才能覆盖运行时克隆出来的节点）找 `帽子基类` 逐个调用 |
| ★真正让取消生效的地方★ | `一步()` 在 `_ctx._已取消` 时只是"让出一帧再返回"，**循环会接着跑下一轮**（实测：切走后计数还在涨）。GDScript 没有取消协程的原语，所以**生成器在每个循环末尾补一句 `if ctx._已取消: break`**（forever / repeat / repeat_until / wait_until 共 5 处） |

**验证**（两个专项脚本，都在 2 屏工程上跑）

`_dev/screen_check.gd`（13 项全通过）：容器两屏共存、初始屏幕=顺序第一个、只有当前屏幕可见、切屏改可见性+画布、非当前屏幕的广播帽子被拦、**非当前屏幕的绿旗照常跑**、切回恢复、**⑥ 切走时正在跑的协程立刻被取消（`_运行中=false`、`_ctx=null`）**、⑦ 切回不误开事件型帽子。

`_dev/screen_lifecycle_check.gd`（5 项全通过，运行时用 `GDScript.new()` 动态造了同款帽子来测）：

③ 切回 → 重新开始（22 → 43）④ **绿旗是全局帽子：切走不被取消**（21 → 41）

**产物核对**：重新转换 `琪露诺` 工程后，14 个含 `while true` 的 screen 帽子**每个循环末尾都带** `if ctx._已取消: break`（内外层都有）。

### 13.8 ★第五轮改动：列表初值 / 大列表外置 / customs 改 AnimatedSprite2D★


**B. 超大列表 → 外置文件（复用超长文本那一套）**

超过 `TEXT_FILE_LIMIT`（1024）字符的列表初值不再内联，落到 `<目录>/文本/列表N.txt`，内容用 **JSON**（列表项有数字也有字符串，按行存会把 `1` 和 `"1"` 混掉）：
```gdscript
var _l_全局列表: Array = []        # 初值太长，_ready 里从外置文件读
func _ready() -> void:
    _l_全局列表 = K4Text.读取列表("全局/文本/列表1.txt")
```

**C. customs：每造型一个 Sprite2D → 一个 AnimatedSprite2D（用户要求的优化）**

以前一个造型一个 `Sprite2D` 子节点，节点树随造型数线性膨胀。现在：

### 13.10 ★第六轮（按键）：`_配置键名()` 断线 + 按键表重构★

### 13.12 ★第八轮（第 20 轮）：custom 造型"缩放" / 名称形参 / 移动方向 + 回归脚本★

**作品与判据**（用户给的）：K4 画板上把「头像」造型的缩放设为 0；作品用随机骰子形象画 Z 字型印章 ——

**① custom 造型的"缩放"是烘进 SVG 自身尺寸的**

`theatre.styles` 里**没有 scale 字段**（只有 `pivot`/`rotate_center`/`adaptive`）：

```

```

该 SVG 是"外壳 + `<image href="data:...">` 内嵌位图"形态，`convert.js` 有一条**快速通道**直接抽内嵌位图
（省掉浏览器光栅化）—— 但它**只取原始位图、无视 SVG 声明的尺寸** → 头像变成一张大图 ✗。

```
      方向 225 移动 100 → (-70.7, +70.7)    期望 (-70.7, -70.7)  （225 = 左下）
```

`deg_to_rad(k4_direction - 90.0)` ✗ → **`deg_to_rad(90.0 - k4_direction)`** ✓（与 `_apply_transform` 配套）。
